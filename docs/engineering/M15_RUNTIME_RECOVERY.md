# M15 production runtime recovery

Status: implementation slice; production exit remains blocked until provider OAuth is completed.

## What this slice repairs

- `api_reconcile_connector_readiness` checks whether each connector account has
  actual token material in the encrypted shared vault, without returning token
  values or ciphertext.
- In vault-required worker mode, active accounts with a missing token are moved
  to `reauth_required`. Revoked and disabled accounts are never reopened.
- `api_reconcile_terminal_outbox` acknowledges only the allowlisted internal
  capture/ingest events whose linked `processing_jobs` row is already terminal.
- Historical `job_id` and current `jobId` payload forms are both supported.
- Every applied readiness correction and terminal-outbox batch is written to
  `audit_log`.

The reconciliation is bounded (`1..1000` events per call), uses row locking with
`SKIP LOCKED`, and is idempotent. It does not publish arbitrary event types,
retry dead letters, create credentials, or claim live connector success.

## Worker behavior

The Node connector tick now runs in this order:

1. inspect connector readiness;
2. when `MEMORY_OS_CONNECTOR_PULL_MODE=vault`, mark missing-token active
   accounts `reauth_required`;
3. dead-letter genuinely stale queued/running jobs;
4. reconcile terminal capture/ingest outbox events;
5. enqueue and claim only `connected` connector accounts.

## Production acceptance

After the migration is applied, run one connector tick with the production
vault configuration. Acceptance evidence must show:

- no unpublished terminal `capture.text.queued`, `capture.document.queued`, or
  `ingest.succeeded` events;
- no active connector is `connected` without token material;
- a provider-authorized connector completes a vault-backed sync, discovers at
  least one selected collection, writes a source event, and can be retrieved;
- revoke stops future enqueue and removes token material;
- logs and reports expose only presence booleans and vault references, never
  access tokens, refresh tokens, plaintext, or ciphertext.

## External action still required

OAuth token material cannot be generated by a database migration or a test
fixture. The current production registrations require real GitHub/Google
authorization after provider client credentials and callback URLs are
configured. Until that consent is completed, the correct production state is
`reauth_required`, not `connected` and not a synthetic PASS.
